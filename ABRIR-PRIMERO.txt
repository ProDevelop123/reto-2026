Sistema de dos APIs comunicadas por HTTP, con frontend y contenerizacion.

  api-go     Recibe una matriz rectangular, calcula su factorizacion QR
             mediante reflexiones de Householder y orquesta la llamada al
             segundo servicio.   (Go 1.25 + Fiber v3)

  api-node   Calcula estadisticas sobre las matrices resultantes: maximo,
             minimo, promedio, suma total y deteccion de matriz diagonal.
             (Node 22 + Express 5)

  frontend   Interfaz que consume el sistema y verifica su correccion
             matematica en el navegador.   (React 19 + Vite)
             Vive en un repositorio aparte, para que Vercel lo despliegue
             de forma automatica.

REPOSITORIOS

  Backend    https://github.com/ProDevelop123/reto-2026
  Frontend   https://github.com/ProDevelop123/factorizacion-QR

-------------------------------------------------------------------------------
  B.1  BACKEND - las dos APIs
-------------------------------------------------------------------------------

REQUISITO UNICO:  Docker Desktop en marcha.

No hace falta instalar Go, ni Node, ni openssl, ni generar claves a mano.

    git clone https://github.com/ProDevelop123/reto-2026.git
    cd reto-2026
    docker compose up -d --build

Y ya esta. El primer arranque tarda un par de minutos porque compila las dos
imagenes desde cero.

Que ocurre al ejecutarlo:

    1. Un contenedor de inicializacion genera el par de claves RSA en ./keys
       si no existe. Las claves NO viajan en el repositorio: cada entorno
       genera las suyas.
    2. Arranca la API de estadisticas y se espera a que responda.
    3. Arranca la API de factorizacion.

Comprobar que ambas estan sanas:

    docker compose ps

Debe mostrar "healthy" en api-go y api-node. El servicio init-keys aparece
como "exited (0)": es correcto, su trabajo es generar las claves y terminar.

    URL de la API      http://localhost:8080
    Comprobacion       http://localhost:8080/health

NOTA: api-node no publica ningun puerto al host, a proposito. Es un servicio
interno al que solo llega la API en Go por la red del compose. No es un
fallo: es la topologia que se quiso demostrar.


-------------------------------------------------------------------------------
  B.2  COMPROBAR QUE FUNCIONA
-------------------------------------------------------------------------------

Requiere Node 18 o superior instalado (solo para lanzar el script; no
instala ninguna dependencia).

    node tests/e2e/run.mjs

Ejecuta 38 comprobaciones contra los contenedores en marcha: autenticacion,
factorizacion, orquestacion entre servicios, validacion de entrada, rotacion
de tokens, proteccion CSRF y aislamiento de red. Ademas RECALCULA por su
cuenta la correccion matematica del resultado.

Deberia terminar con "38 correctas, 0 fallidas".

Si no se tiene Node, se puede probar la API a mano:

    curl -X POST http://localhost:8080/api/v1/auth/login ^
      -H "Content-Type: application/json" ^
      -d "{\"username\":\"admin\",\"password\":\"Reto2026.Demo\"}"

(en Linux o macOS, sustituir el ^ final de linea por \)


-------------------------------------------------------------------------------
  B.3  FRONTEND
-------------------------------------------------------------------------------

REQUISITOS:  Node 20 o superior, y el backend del paso B.1 en marcha.

    git clone https://github.com/ProDevelop123/factorizacion-QR.git
    cd factorizacion-QR
    pnpm install
    pnpm dev

Y abrir:  http://localhost:5173

    Usuario      admin
    Contrasena   Reto2026.Demo

Si no se tiene pnpm:

    corepack enable

(corepack viene incluido con Node 16.9 y posteriores; el proyecto fija la
version exacta del gestor en package.json, asi que se instalara sola)

NO hace falta crear ningun fichero .env: el valor por defecto ya apunta a
http://localhost:8080, que es donde escucha el backend.

El puerto 5173 es fijo a proposito: es el origen que la API en Go declara
como permitido. Si estuviera ocupado, Vite fallara al arrancar en lugar de
elegir otro puerto en silencio, porque hacerlo provocaria errores de CORS
dificiles de diagnosticar.


===============================================================================
  QUE MIRAR
===============================================================================

En la aplicacion hay cinco botones de ejemplo. Ninguno es decorativo: cada
uno demuestra una propiedad concreta del algoritmo.

  Clasica 3x3          La matriz canonica de los libros de algebra lineal.
  Rectangular 3x2      Matriz no cuadrada, como pide el enunciado.
  Diagonal             Activa el indicador de matriz diagonal.
  Rango deficiente     Caso limite que rompe implementaciones ingenuas.
  Mal condicionada     Matriz de Lauchli. Mirar el panel de verificacion:
                       la ortogonalidad se mantiene en 1e-15, mientras que
                       Gram-Schmidt clasico se desplomaria a 0.5.

El panel "Verificacion independiente" no muestra datos que devuelva la API:
recalcula Q*R y Q^T*Q en el navegador y mide los residuos. El cliente no
confia en el servidor, lo comprueba.

Cada bloque del resultado indica que componente lo produjo: la factorizacion
viene de la API en Go, las estadisticas de la API en Node, y los residuos se
calculan en el navegador.

===============================================================================
  SI ALGO FALLA
===============================================================================

  El comando "docker compose" no existe
      Docker Desktop no esta instalado o no esta en marcha. Con versiones
      antiguas el comando es "docker-compose" con guion.

  Un servicio no llega a "healthy"
      docker compose logs api-go
      docker compose logs api-node
      La validacion de configuracion indica exactamente que falta.

  init-keys aparece como "exited"
      Es correcto. Genera las claves y termina; no es un servicio que deba
      permanecer en marcha.

  El puerto 8080 esta ocupado
      Crear un fichero .env en la raiz con:  API_PORT=9090
      Y volver a ejecutar docker compose up -d

  Todas las peticiones devuelven 502
      La API de estadisticas no esta sana. Revisar docker compose ps.

  Error de CORS en el navegador
      El frontend debe servirse en el puerto 5173, que es el origen que la
      API declara como permitido.

  "docker compose exec ... sh" no funciona
      Es correcto: las imagenes son distroless y no contienen shell. Para
      sondear la API en Go:  docker compose exec api-go /app/api healthcheck

  Empezar de cero
      docker compose down -v
      docker compose up -d --build
